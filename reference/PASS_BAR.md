# PASS BAR — the nine lines every framework must clear (fixed; computed by `tools/judge_run.py`; changed only by a human via escalation)

**Version 2026-10-13 (Dominik).** This is a **triage** bar: PASS sends the experiment to Human Review, where a person decides whether it goes to the production replica (governor 2×2, 2× costs, paired-t adoption rule). It is therefore inclusive on magnitude — a standalone net Sharpe of 0.7–0.8 that is uncorrelated with the book is worth a look (adding an uncorrelated 0.75 to a 2.0 book lifts it to ≈ 2.14) — and strict on fakeness (placebo, concentration, cost fragility, costume of an existing sleeve). The previous bar (Sharpe ≥ 1.0 in each window) was a t-stat of ≈ 1.4 on the 2-year window and would have hidden exactly the sleeves a multi-alpha book wants.

All numbers are for the **chosen configuration** (the sweep's best point, selected on the calibration window only) run over the full sample (calibration and evaluation as separate segments, Obsidian's convention) through **Obsidian's production-replica engine, hourly** (`tools/obsidian_engine.py` = `backtest/engine_v2.py` verbatim) **with no drawdown governor** — per-name caps, max-loss tiers, gross cap, no-trade band, participation cap, BTC hedge, full cost model, per-print funding, 1× gross target. Neither the step ladder nor the CPPI governor is applied in the harness (a governor parked at its floor flattens the NAV line for months and the backtest then measures the brake, not the signal; drawdown control is a deployment question, handled after Human Review). Statistics start on the **first traded day** (warm-up days before the signal exists are excluded and counted). Every line must pass; the result comment prints each with its number.

| # | line | rule | why it is there |
|---|---|---|---|
| 1 | Sharpe, each window | calibration (2022-01 → 2023-12) Sharpe ≥ 0.5 **and** evaluation (2024-01 → last completed month end) Sharpe ≥ 0.75 | the 2-year window can only confirm the sign and rough size (its Sharpe has a standard error of ≈ 0.9); the untouched window carries the stricter number |
| 2 | Significance | full-sample t-stat of the daily returns ≥ 1.65 (one-sided 95 %; ≈ Sharpe 0.75 over the current 4.7 years — the Sharpe equivalent falls as the window grows, the t does not) | the one test with real power; replaces "Sharpe ≥ 1.0 full" so the gate does not silently tighten every month |
| 3 | Return | evaluation annualised net return ≥ 5 % at the standard 1× target | rules out a Sharpe on a rounding error; note realised gross after caps is 0.3–1.2×, so 5 % on NAV is 5–15 % on gross |
| 4 | Drawdown | maximum drawdown over the full sample ≤ 20 % (NAV, daily; no governor) | wide enough that the governor-free run is judged on its signal; the production program's 10 % hard stop is applied at deployment, with a governor |
| 5 | Cost stress | Sharpe at 2× fee, spread and impact (full sample) > 0.4 | ≈ 2/3 of the primary bar, as before; a framework that dies at 2× has no margin for a bad execution month |
| 6 | Placebo | mean \|t\| of the daily returns over three fixed random relabellings of the names (seeds 1–3) < 1.5 | if shuffled names do as well, the construction (hedge, caps, sizing) is earning the return, not the ranking — never loosened |
| 7 | Parameter plateau | median calibration Sharpe of the grid points within ±50 % of every chosen parameter ≥ 0.5 (alternatives must match the chosen ones) | a knife-edge optimum is a sweep artefact; "no tunables" passes vacuously |
| 8 | Concentration | the top 5 names' share of positive per-name P&L ≤ 50 % | an effect that lives in five names is an anecdote, and is uncapturable at size |
| 9 | Diversification | max \|daily-return correlation\| with the three production sleeves (FundingCarry, IlliquidityPremium, TakerFlow-R; `examples/ref_*.json`) ≤ 0.7 | the industry's "is it a costume" test; IlliquidityPremium and TakerFlow-R correlate 0.84 with each other, so a new sleeve at 0.85 to either is a relabelling. Passes vacuously only when the reference sleeves were not run (`--quick`, never for a verdict) |

**STRONG.** A PASS that also clears Sharpe ≥ 1.0 in both windows is stamped STRONG in the result (Strength line and the For-Scout watch list) so the Human Review queue can be prioritised. It changes no status.

Reported but not gated (they feed the reading and the **For Scout** line): first traded day and warm-up days excluded, raw-sleeve Sharpe (no caps / hedge), funding P&L per year, cost drag per year, turnover, worst 1 / 7 / 30-day returns, per-year table, the full sweep grid (best / median / worst calibration Sharpe).

Windows: `CALIB = 2022-01-01 → 2023-12-31`; evaluation from 2024-01-01 to `--eval-end` (default: the last completed month end at run time). Data begins 2021-10-01 so that 60-day betas and 21-day medians exist on the first calibration day. These constants and the `BAR` dictionary live at the top of `tools/judge_run.py` and nowhere else.

Reference points (standalone production alphas through this engine, 2026-10-13, `results/alpha_cards/` in the Obsidian repo): FundingCarry calib / eval Sharpe 1.23 / 1.33, IlliquidityPremium 1.04 / 1.58, TakerFlow-R 1.49 / 1.45 — all PASS and STRONG; the whole book ungoverned 1.48 / 2.13 with a 25 % max drawdown (the governor brings it to 8 %).

Verdict: **PASS** → Human Review. **FAIL** → Critiqued (round < 5) or Discarded (round 5). No other outcomes; no partial credit; no "promising".
